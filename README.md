# 个人技术站 · 使用说明

**站点地址：<https://shiguangxiaoji.com>**

写涂层失效、腐蚀防护与评价方法的公开笔记。零依赖静态站：Hugo 生成 HTML，Nginx 只负责发文件。目标机器是阿里云 ECS 2 核 2G / 3M 带宽。

## 一、日常三步

```bash
cd ~/WorkBuddy/个人网站

# 1) 新建一篇文章（自动进草稿，draft: true）
./bin/hugo new notes/我的新笔记.md

# 2) 本地预览（改文件会自动刷新）
./bin/hugo server -D

# 3) 发布：把 draft 改成 false，然后构建 + 上传
./deploy/deploy.sh
```

浏览器打开 <http://localhost:1313> 预览。`-D` 表示连草稿一起显示。

**排期与提醒**：`发文计划_2026-11至2027-11_周更52篇.md` 是排期表正文（周更 52 篇：26 重文 + 26 轻文），`技术站日历.ics` 是它的日历版（52 个发文事件 + 3 个运维事件、78 条提醒，导入系统日历即用）。旧版 `发表顺序_A系列.md` 仅作存档，重文日期与新计划完全一致。注意 `hugo.toml` 未开 `buildFuture`，**front matter 写未来日期时构建不生成该页**，必须等当天再跑 `deploy.sh`；预览请用 `./bin/hugo server -D -F`。

## 四、写文章的约定

每篇文章的头信息（front matter）：

```yaml
---
title: "标题"
date: 2026-10-22
draft: false                  # true = 只在本地预览可见
description: "一句话说清这篇回答什么问题（会出现在列表和搜索结果里）"
section_label: "方法库"
tags: ["实证", "数据分析"]
---
```

正文用普通 Markdown。支持标题、列表、表格、引用、代码块。

### 英文摘要（English Summary）

每篇正文末尾加一节英文摘要，**位置固定在文末免责声明之前**（免责声明永远留在最末）。

```markdown
## English Summary

The 60% relative humidity figure is not a safety threshold. It is the humidity
at which the finest pores on a steel surface fill with water...
```

写法硬规则：

| # | 规则 | 说明 |
|---|---|---|
| 1 | **150–200 词** | 一段或两段，不分小节。超过 200 词就不是摘要，是翻译 |
| 2 | **只写论点与边界** | 不复述全文、不逐段对应中文。写完自问：这句有没有增加中文里没有的信息？没有就删 |
| 3 | **至少一个硬信息** | 数字、标准编号（ISO 4628-8 / ASTM D1654 / ISO 9223）或明确的适用条件 |
| 4 | **禁套话** | 不用「This article introduces / discusses…」。第一句直接给判断 |
| 5 | **术语用国际通用写法** | cathodic disbondment、filiform corrosion、critical relative humidity、time of wetness (TOW)、Pilling–Bedworth ratio |
| 6 | **短句优先** | 中文的长定语从句拆两句。宁可句子多，不要一句三行 |
| 7 | **数字用国际口径** | nm / µm / mm / MPa、百分号；不出现「万」「亿」 |
| 8 | **红线与中文正文同一套** | 不出现公司名、客户名、项目名、配方与成本（见 §五） |

两条判断依据：

> **为什么不做全文翻译**：英文读者手上有 NACE / SSPC / ISO 原文，缺的是判断不是信息；而全文翻译的质量天花板受限于校对能力——判断翻错比不翻更伤。
> **为什么必须自己写初稿**：这是唯一的英语写作训练场。一年 52 篇 × 150 词 ≈ 7800 词，量刚好够练又不压垮。先自己写、再让 AI 逐句改，比读十篇方法论有用。

**不做的事**：不加 `[languages.en]`、不建 `/en/` 目录、不加 hreflang、不改模板。等技术性判断有把握了，再谈全文英文版。

## 五、发布红线（公司统一口径 · 硬约束）

### 5.0 规则原文

> **只能转发公司公众号上已经发表的相关内容；其余一切与公司相关的内容，均不得发表在互联网上。**

这是硬约束，不是「注意一下」。它改变了判定标准：**不看你怎么写，看知识从哪来。**

### 5.1 判定标准已从「呈现」改为「来源」

| 旧标准（已废止） | 新标准（现行） |
|---|---|
| 脱敏、去数值、去主体后就能发 | **脱敏不算数。来源是公司，就不能发** |

原因很实在：**脱敏解决的是「看不看得出来」，公司管的是「是不是你的东西」。** 这两件事不在一个维度上。一篇完全没有数字、但方法来自公司项目的文章，仍然属于「与公司相关的内容」。

### 5.2 三档判定（按来源）

| 档 | 来源 | 举例 | 处理 |
|---|---|---|---|
| **① 可发** | 公开标准条文、教科书、公开文献、公开行业报告 | IEC/ISO/ASTM 条款解读、腐蚀与涂层机理、可靠性统计方法、术语辨析 | 发，文中注明引用来源 |
| **② 只可转发** | 公司公众号已发表内容 | 官方技术文章、官方产品介绍 | 注明出处 + 原文链接，**不改写、不摘编、不二次演绎** |
| **③ 禁止** | 公司项目、公司数据、公司产品与工艺、公司流程与体系实践、客户与供应商、以及**基于公司工作形成的方法论** | 实证方法、BOM 筛选判据、NPI 记录、体系扩项做法、任何可指向公司业务的结论 | **不上，任何形式都不上**（含换说法、只放一张图、只给百分比、只讲方法不给数） |

⚠️ ①档里「**IEC/ISO/ASTM 条款解读**」这一项有两条附加限定（2026-10-31 补）：

1. **不得以现公司业务对象为案例**——组件结构、封装方案、具体测试条件怎么定够不够，一律不写。
2. **不得面向特定行业岗位写作**——受众写「刚入行的测试工程师」，不写「组件测试工程师」。受众行业化本身就是身份信号。

标准类文章只写**标准为什么这样编排**（条款为什么留空、序列为什么是树、样品数为什么随序列变），不写「我怎么判读」。落地口径与熔断条件见 `发文计划_2026-11至2027-11_周更52篇.md` 第三节 P 系列说明。

⚠️ 第 ③ 档最容易踩的不是数据，是**方法论**。「我怎么筛 BOM」「我怎么算衰减」这类内容，即使一个数字都没有，也是在公司岗位上形成的，属于公司工作成果。

### 5.3 发布前三问（任一不过就不发）

1. **这个知识，我是从公开来源学的，还是从公司工作里得的？** 后者一律不发。
2. **它属于公司的业务领域吗？**（例：光伏组件与封装 = 公司领域，即使讲通用原理也高风险）
3. **假设明天被转到公司群，我能说清来源是公开资料吗？** 说不清就不发。

### 5.4 转发公司公众号的四条

1. **只转已发表的，不转内部稿、不转未发布预告。**
2. **注明出处 + 原文链接**，标题与正文不改动。摘编、缩写、加自己的解读 → 变成「二次创作」，越界。
3. **不署自己的名**，也不放在「我的文章」栏目里。转载≠作品。
4. **最好先问一句品牌/市场部**：公众号内容转载到个人站，多数公司允许，但有的要求报备。问一句的成本远低于事后解释。

### 5.5 个人备案的另外三条

不做经营性内容、不放广告、不开评论区（UGC 需审核，容易被要求整改）。备案被注销比删一篇文章严重得多——域名在大陆直接失效。

### 5.6 当前状态（2026-10-22）

原有 6 篇文章**全部转为草稿下线**（`draft: true`），因为它们全部属于第 ③ 档：来自光伏组件与封装的公司工作。线上目前只有栏目页与「关于」页。

重新上线走 `选题池_合规版.md` 的白名单，不从旧稿改。

## 六、服务器侧（宝塔面板 · 已配好，不要再改）

| 项 | 值 |
|---|---|
| 服务器 | 阿里云 ECS 2 核 2G，Ubuntu 22.04.5 |
| 面板 | 宝塔 13.1.0，端口 8888 |
| 站点根目录 | `/www/wwwroot/shiguangxiaoji.com`（属主 `www:www`） |
| Nginx | 宝塔自编译 `/www/server/nginx/`，**不是** `/etc/nginx` |
| 站点配置 | `/www/server/panel/vhost/nginx/shiguangxiaoji.com.conf`，由面板生成 |
| 证书 | DigiCert 免费 DV，2026-10-30 签发，2027-01-27 到期 |

**`deploy/nginx.conf` 已作废**——那是系统 Nginx 的写法，宝塔会覆盖它。HTTPS、80→443 跳转、gzip、证书全部由面板管，不要手改。

部署只做一件事：同步文件。

```bash
./deploy/deploy.sh
```

rsync 会**排除** `.user.ini` / `.htaccess` / `.well-known`——这三个是宝塔生成的，`--delete` 删掉会破坏面板配置（`.user.ini` 还被 chattr 锁了，chown 会报 Operation not permitted，脚本里已跳过）。

首次打通免密（服务器地址写在 `deploy/.deploy.env` 的 `DEPLOY_HOST` 里，该文件不进仓库）：

```bash
ssh-copy-id -i ~/.ssh/id_ed25519.pub root@你的服务器IP
```

**每季度要看的**：宝塔 → 网站 → SSL → 确认「自动续签」是开的。证书只有 3 个月有效期。

### 6.1 恶意扫描屏蔽（2026-11-25 加）

访问日志里 404 曾累计 1.9 万次，绝大多数是 `/.env`、`/.git/config`、`/.ssh/id_rsa`、`wp-admin`、`phpmyadmin`、`/v1/models` 这类漏洞探测（全部 404，无一得手）。现在统一返回 `444`（直接断连，不响应内容、不写日志）。

| 项 | 路径 |
|---|---|
| 规则文件（服务器） | `/www/server/panel/vhost/nginx/extension/shiguangxiaoji.com/block-scanners.conf` |
| 本地存档 | `deploy/nginx-block-scanners.conf`（重装服务器时 scp 上去即可恢复） |
| 为何放这里 | 站点配置第 14 行已 `include .../extension/shiguangxiaoji.com/*.conf`，**面板重写站点配置也不会覆盖** |

**两个硬注意**：
1. 规则里第一条必须是 `location ^~ /.well-known/ { allow all; }` —— 否则 SSL 证书续期（acme challenge）会被 444 打死。
2. 改完必须 `/www/server/nginx/sbin/nginx -t` 通过后再 `nginx -s reload`，不能直接重启。

**favicon** 由 `deploy/make_favicon.py` 生成（纯标准库，不依赖 Pillow），输出 `static/favicon.ico`（16/32/48）与 `static/favicon.svg`。改图形只需改脚本里的 `BARS` 常量后重跑。

## 七、为什么不用 WordPress

| | 本方案 | WordPress |
|---|---|---|
| 内存占用 | ~80 MB | 600–800 MB（含 MySQL） |
| 首页响应 | 纯静态，几十毫秒 | 现场拼页面，2G 上偏慢 |
| 攻击面 | 只有 Nginx | 插件与后台是常见入口 |
| 备份 | 整个 public 目录，~200 KB | 数据库 + 上传目录 |

2 核 2G 跑静态站绰绰有余，跑 WordPress 刚好卡在边缘。

## 八、GitHub 公开镜像（拿到外链用）

仓库里有两个分支，分工明确：

| 分支 | 内容 | 是否推送 |
|---|---|---|
| `main` | 完整工作分支，含未发布草稿与内部排期文档 | **不推** |
| `publish` | 干净快照，只有 45 个可公开文件，**单条提交、零历史** | 推到 GitHub |

**为什么要有 `publish`**：`main` 的历史里含草稿全文，一旦公开就无法收回。`publish` 是孤儿提交（无父提交），推上去后别人翻历史也只看得到这一条干净记录。

**首次推送**：

```bash
git push -u origin publish:main
```

**以后更新**（改了内容后同步到公开分支）：

```bash
git checkout publish
git checkout main -- .          # 按 .gitignore 取当前可公开文件
git add -A
git commit --amend -m "静态站点源码快照"
git checkout main
git push origin publish:main --force
```

> `--force` 是必要的：`publish` 每次都重建单条提交，远程也保持"永远只有一条"。

**不进公开仓库的东西**（见 `.gitignore`）：未发布草稿、选题池与发文计划、素材卡、`deploy/.deploy.env`（服务器 IP）、`public/` 构建产物。
